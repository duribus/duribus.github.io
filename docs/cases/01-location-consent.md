# 개선 사례 01. 위치 동의 안내로 '가까운 정류장' 사용률 높이기

> 기간: 2026-11-27(금) ~ 11-28(토) · 데이터: GoatCounter 익명 이벤트

## 1. 문제 발견
- 출시 첫날(11/27) 새로 들어온 기기 35대 중 '현재 위치' 버튼을 누른 건 2번(약 6%).
- '처음 보이는 정류장'이 기본값(새롬관)인 경우가 49번 → 대부분 기본 화면만 보고 나감.
- 내 위치와 상관없는 정류장 시간을 보게 되는 사용자가 많다는 뜻.

## 2. 가설
- 버튼이 있다는 걸 모르거나, **위치를 왜 쓰는지 모르면 권한을 주기 꺼린다.**
- 권한 요청 전에 '어디에 쓰는지 / 저장하지 않는다'를 먼저 설명하면 동의가 늘 것이다.

## 3. 해결
- 첫 방문 시 한 번만 뜨는 안내 시트 추가 (브라우저 권한 창보다 먼저)
  - "가까운 정류장을 자동으로 찾을까요?"
  - 위치는 기기 안에서만 계산 · 저장·전송 안 함 · 언제든 끌 수 있음 (3줄)
  - [위치 사용하기] / [직접 고를게요]
- 이미 허용·거부한 사용자에게는 띄우지 않음, 거절하면 다시 묻지 않음
- 측정 이벤트 추가: `위치안내/표시 · 허용 · 건너뜀`, `위치/클릭`, `위치/실패/권한거부 · 오류`

## 4. 결과
| 지표 | 개선 전 (11/27) | 개선 후 (11/28) |
|---|---|---|
| 새 기기 수 | 35 | 8 |
| 위치 기능 사용 시도율 | 2 / 35 ≈ **6%** | 6 / 8 = **75%** (안내 동의율) |
| 위치로 정류장 자동 선택 성공 | 1 / 35 ≈ 3% | 2 / 8 = 25% |
| 안내 건너뜀 | - | 1 / 8 |
| 실패 | 오류 1 | 권한거부 1, 오류 1 |

## 5. 배운 점 / 다음 할 일
- **설명 후 요청(pre-permission)**만으로 동의가 크게 늘었다.
- 하지만 동의 6명 중 성공은 2명 → **'동의 이후' 단계가 새 병목.**
  - 권한거부: 안내에선 동의했지만 OS 권한 창에서 거절 → 안내 문구와 OS 창 사이 기대 차이
  - 오류: 에타·카톡 인앱 브라우저에서 위치가 막히는 경우로 추정 → 인앱 안내 강화 필요
- 다음 실험: 인앱 브라우저 감지 시 '브라우저로 열기' 안내를 위치 요청 전에 먼저 보여주기

## 6. 한계
- 표본이 작다(개선 후 8대). 평일(금)과 주말(토)로 사용 맥락도 다르다.
- 개선 전 지표는 '버튼 클릭', 개선 후는 '안내 동의'라 측정 시점이 다르다.
- 1~2주 데이터가 더 쌓이면 같은 기준(새 기기 대비 위치 성공률)으로 다시 비교할 것.
